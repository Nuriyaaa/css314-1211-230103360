## Final Conclusion

This project evaluated parallel computing performance on an Apple M4 system using Python 3.14.3.

The experiments covered hardware calibration, false sharing, strong and weak scaling, empirical roofline analysis, matrix multiplication, and load balancing.

The strong scaling experiment achieved a speedup of 4.5089 with 10 processes. However, parallel efficiency decreased as the number of processes increased.

The false sharing experiment did not show a significant performance difference between stride 1 and stride 16.

The empirical roofline experiment measured a memory bandwidth of 2.6485 GB/s and a compute throughput of 1.008416 GFLOP/s.

For matrix multiplication, the reordered i-k-j implementation was faster than the naive implementation. The best tiled configuration used a tile size of 128.

For load balancing, dynamic scheduling with chunk size 16 achieved the lowest execution time.

Overall, the experiments showed that parallel performance depends not only on the number of processes but also on workload distribution, memory access patterns, scheduling overhead, and implementation details.
